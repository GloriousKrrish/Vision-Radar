## 2. Investigation of Current UI Overlay Problem

### Problem Statement
The UI displays **JOB COMPLETED**, but the user sees raw video without clearly visible AI bounding boxes or overlay labels.

### Diagnostic Verification Matrix (15 Verification Points)

1. **Are frames actually processed?**  
   👉 **YES.** All 335 frames are fully decoded and passed to the inference pipeline.
2. **Are YOLOX detections generated?**  
   👉 **YES.** 1,685 vehicle bounding boxes are generated by OpenCV DNN.
3. **Are ByteTrack tracks generated?**  
   👉 **YES.** 31 distinct track objects are created and maintained across frames.
4. **Are FrameResults generated?**  
   👉 **YES.** `job_worker.py` creates incremental `frame_result` dictionary payloads.
5. **Are FrameResults stored?**  
   👉 **YES.** Saved to SQLite `tracks` and `speed_measurements` tables at job completion.
6. **Is the frontend receiving them?**  
   👉 **YES.** Received via WebSocket during streaming, and via `GET /api/v1/jobs/{job_id}/tracks` post-completion.
7. **Is the frontend rendering them?**  
   👉 **BROKEN / ULTRA-FAINT.**
8. **Is the displayed frame synchronized with the AI frame?**  
   👉 **YES.** During streaming, `currentTime` is locked to `frame_index / fps`.
9. **Is the selected job ID correct?**  
   👉 **YES**, when explicitly selected. However, on page load, `activeJobId` is unselected, leaving the React app in `'EMPTY'` mode.
10. **Is the frontend accidentally showing only the raw HTML/video element?**  
    👉 **YES.** The frontend renders a background `<video>` element on `<canvas>`. When overlay styling is faint or uncalibrated, the background video overwhelms the overlay.
11. **Is WebSocket connected?**  
    👉 **YES.** Connection to `/api/v1/jobs/{job_id}/stream` succeeds cleanly.
12. **Does REST fallback work?**  
    👉 **YES.** `/api/v1/jobs/{job_id}/tracks` returns full trajectory data.
13. **Is calibration incorrectly blocking DETECTION/TRACKING?**  
    👉 **NO.** YOLOX detection and ByteTrack run without calibration.
14. **Is calibration only blocking SPEED/DENSITY?**  
    👉 **YES.** Without calibration, speed estimation returns `speedStatus = "CALIBRATION_REQUIRED"`.
15. **Are detections present but visually hidden?**  
    👉 **YES! CRITICAL FRONTEND BUG DISCOVERED (`apps/web/src/components/WorkbenchView.tsx`):**
    - Line 592: `isCalibRequired = !realCalib || det.speedStatus === 'CALIBRATION_REQUIRED';`
    - Line 598: `col = isCalibRequired ? '#64748B' : ...` (Slate Grey).
    - Line 602: `cx.fillStyle = isSelected ? '#F59E0B25' : (col + '1A');` -> `(col + '1A')` translates to `#64748B1A` (**10% opacity slate grey** fill box!).
    - Line 613: Bounding box stroke is drawn in thin slate grey.
    - When a video is freshly uploaded, `calibration_id` is initialized to `null`.
    - As a result, **ALL vehicle bounding boxes render in 10% opacity slate grey (`#64748B1A`) with label `"CALIBRATION REQUIRED"`, making them nearly invisible against moving asphalt video!**

## 4. Accident Dataset Audit Summary

- **Dataset Path:** `DATASETS/Accident` (6,191 JPEG images + 1 Jupyter Notebook)
- **Dataset Type:** Static Image Classification (Accident vs Normal Scene)
- **Bounding Boxes:** None
- **Temporal Video Data:** None (Isolated photographic stills)
- **Compatibility with YOLOX / VisionRadar Pipeline:** **Incompatible.** The dataset consists of independent static photos without bounding boxes or temporal track sequences. It cannot be used directly for real-time video accident detection in YOLOX or ByteTrack.
